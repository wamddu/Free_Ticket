> 작성일 당시의 측정·검증 기록이다. 본문의 `artifacts/…` 경로에 있던 원시 데이터(CSV, 로그, 측정 스크립트)는 용량 때문에 저장소에 포함하지 않았고, 서버 주소는 `<EC2 주소>`로 가렸다.

## 검증 범위

Chrome에서 사용자가 새 테스트 결제를 승인한 뒤, 토스 취소 API로 취소하고 현재 백엔드의 실제 `@Scheduled` 작업이 거래 조회 API를 통해 불일치를 자동 기록하는지 확인한다.

테스트 키를 사용하는 샌드박스 검증이다. 실제 금전 결제와 라이브 운영 검증은 포함하지 않는다.

## 환경과 조건

- DB: `free_ticket_recon_e2e_20260928_84a308d1` — 기존 서비스 DB와 분리.
- 사용자 결제 화면: 프런트엔드 5174, 백엔드 18080.
- 자동 대사 작업: 별도 백엔드 18081에서 현재 소스의 스케줄러 실행.
- MID 최대 길이 14자 유지. 이번 신규 결제의 실제 MID 길이는 모두 9자.
- 최근 거래를 10분간 제외하는 코드 유지. 테스트에서만 실행 간격을 30초로 설정.
- 대사 조회 시작 지점을 신규 취소 직전인 `2026-09-28T23:34:12+09:00`로 설정.
- 주문 복구 스케줄러는 테스트에서 비활성화.
- 외부 취소 후 로컬 주문·결제·재고는 수정하지 않아 불일치 상태를 만든다.
- 이전 검증에서 만든 로컬 fixture는 이번 신규 주문 검증 결과에서 제외한다.

각 취소 전에 실제 토스 응답의 주문번호·결제 키·금액·상태가 격리 DB의 사용자 신규 주문과 일치하는지 확인했다. 결제 키와 시크릿 키는 보고서에 포함하지 않는다.

첫 번째 주문에서 부분 취소 후 잔액까지 취소해도 상태가 `PARTIAL_CANCELED`로 유지되는 응답이 관찰되었다. 그래서 `CANCELED` 분기는 두 번째 신규 결제를 한 번에 전액 취소하여 별도로 검증한다. 이 관찰만으로 모든 결제수단·라이브 환경의 상태 규칙을 단정하지 않는다.

## 자동 감지 확인

10분 제외 조건이 지나기 전, 신규 주문의 불일치 기록은 0건이며 두 로컬 주문은 `PAID`, 결제는 `DONE`, 테스트 티켓의 판매 수는 4였다. 판매 수 4 중 2는 이전 fixture이고 2는 이번 신규 승인이다.

23:44:35 KST에 실제 스케줄러가 토스 거래 2건을 조회했고, `PAID_PG_PARTIAL_CANCELED` 기록 2건을 자동 저장했다. DB에 저장된 거래 시각은 각각 14:34:13 UTC, 14:34:14 UTC로 토스의 +09:00 시각과 일치한다. 두 기록의 로컬 상태 스냅샷은 `PAID/DONE`, MID 길이는 9자였다.

```
2026-09-28T23:44:36.559+09:00
Payment reconciliation finished: windows=1, transactions=2, newIssues=2,
completedThrough=2026-09-28T14:34:35Z
```

23:49:38 KST에 두 번째 주문의 전액 취소가 `PAID_PG_CANCELED` 1건으로 자동 저장됐다. 이후 23:50:08 KST 반복 실행에서 `newIssues=0`으로 완료되어 새 불일치 기록은 총 3건으로 유지됐다.

```
2026-09-28T23:49:38.362+09:00
Payment reconciliation finished: windows=1, transactions=9, newIssues=1,
completedThrough=2026-09-28T14:39:38Z

2026-09-28T23:50:08.611+09:00
Payment reconciliation finished: windows=1, transactions=9, newIssues=0,
completedThrough=2026-09-28T14:40:08Z
```

조회 건수 9에는 같은 공용 테스트 키의 다른 거래도 포함된다. 이번에 사용자가 새로 만든 두 주문에서 기록된 불일치만 아래 결과에 집계한다. 조회 응답을 임의로 필터링하거나 스케줄러를 우회하지 않았다.

최종 DB 확인 결과:

- 신규 두 주문 모두 `PAID`, 결제 모두 `DONE` 유지.
- 각 주문·결제의 금액은 10,000원으로 일치하고 결제 키도 일치.
- 판매 수 4 유지. 이번 외부 취소와 대사로 재고가 수정되지 않음.
- 토스의 3개 취소 거래 시각이 UTC로 변환되어 정확히 저장됨.
- 대사 진행 지점이 `2026-09-28T14:40:08Z`까지 전진.
- 새 결제 → 실제 토스 취소 → 10분 제외 → 실제 자동 스케줄러 조회 → DB 기록 → 반복 실행 중복 방지까지 통과.
